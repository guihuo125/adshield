## 一、项目是什么

**Chrome Manifest V3 广告拦截扩展**。四层能力：

| 层 | 做什么 | 技术手段 |
|---|---|---|
| 网络层 | 拦广告/追踪/恶意请求，清理 URL 追踪参数 | DNR 静态规则集 + 动态规则 |
| 页面层 | 隐藏页面上的广告元素、规避反拦截检测 | content script（隔离世界 + MAIN world 双通道） |
| 订阅层 | 在线拉取过滤列表并转成 DNR 规则 | `fetch` + 规则解析器 + 串行队列 |
| 账号层 | 注册登录、云端同步配置、设备管理 | Supabase |

**关键边界**：数据默认只存本地，**只有用户主动注册登录后才同步到云端**。这是产品承诺，
`shared/auth.js` 里的白名单校验与 CSS 注入防护是这条承诺的技术兜底。

### 当前状态（2026-11-01）

刚完成一轮全量代码审查 + 修复 + 重构 + 文档补齐：

- **修复**：2 个 Critical（其一复核为误报）、6 个 Major
- **重构**：抽出 4 个共享模块，消除 5 份重复实现、6 处手写弹窗、3 份漂移的默认配置
- **测试**：从 0 增至 **140 项**（静态校验 + 3 组单元测试 + 运行时诊断自检）
- **文档**：README、AGENTS、架构说明、本交接文档
- **实测**：DNR 常量、端到端规则命中均已在本机 Chrome 156 验证

完整记录见 [`REVIEW-2026-11-01.md`](./REVIEW-2026-11-01.md)。

## 二、上手导航

### 第 1 步：跑起来看现象（5 分钟）

```bash
npm run verify      # 静态校验 + 140 项测试，必须全绿
npm run probe       # 运行时诊断：自动起一个 Chrome 实例采集事实
```

`npm run probe` 会**自启一个独立 Chrome 实例**（临时 profile，不碰你日常浏览器），
加载扩展、采集 DNR 事实、并做三项端到端自检（静态规则是否真命中 / content script 是否注入 /
URL 参数清理是否生效）。**不需要任何手工操作。**

> ### ⚠️ 这个项目有**两个目录**，必须分清
>
> | 目录 | 角色 |
> |---|---|
> | `D:\AdShield 广告拦截器\` | **工作区 / 打包源**。`pack.ps1` 从这里打 CRX/ZIP，代码实际编辑处 |
> | `D:\temp-adshield-repo\` | **Git 仓库**。指向 `https://github.com/guihuo125/adshield.git`，远端 `main` 分支 |
>
> **工作区本身没有 `.git`**——所以在 `D:\AdShield 广告拦截器\` 里敲 `git` 命令会报
> "not a git repository"。**Git 操作要去 `D:\temp-adshield-repo\` 做。**
>
> 两边内容必须保持一致（提交历史里的 `ee33988` 就是"交接文档校正 + 真机验证脚本入库"，
> 说明同步是**手动拷贝 + 提交**，不是 submodule 或软链）。
>
> **给你的硬约束**：
> - 改完代码后，**要记得同步到 `D:\temp-adshield-repo\` 再提交**，
>   否则改动只留在工作区，远端看不到、也没有版本历史。
> - 工作区没有版本历史，**改大文件（`background.js` / `auth.js` / `options.js`）前先手动备份**，
>   否则改错了无法回滚、无法 diff。
> - `.gitignore` 已排除 `.keys/`、`*.pem`、`*.key`、`*.crx`、`*.zip`。
>   **签名密钥绝不能进版本库。**

### 第 3 步：认代码（2 小时）

按这个顺序读，能最快建立心智模型：

```
1. adblocker/manifest.json                    ← 30 行，看清全貌：8 项权限、5 个规则集、3 个 content script
2. adblocker/src/shared/host.js               ← 96 行，host 归一化的单一真源
3. adblocker/src/shared/config.js             ← 96 行，默认设置 + 消息协议
4. adblocker/src/background.js 的这几块：
   - getSettings()            第 26 行    ← 设置读取（所有 storage 访问的入口）
   - syncGlobalPauseRule()    第 61 行    ← 全局暂停
   - syncRulesets()           第 102 行   ← 静态规则集开关
   - syncSiteAllowlist()      第 144 行   ← 站点放行（白名单 → DNR allow 规则）
   - applyUserRules()         第 456 行   ← 用户自定义规则下发
   - applySubscriptionText()  第 602 行   ← 订阅规则解析与下发
   - handleOtherMessage()     第 937 行   ← 消息总线（所有跨模块通信的入口）
5. adblocker/src/content/cosmetic.js：
   - buildCss()               第 119 行   ← 选择器 → CSS
   - pickUserSelectors()      第 141 行   ← 用户 ## 规则解析
   - domainsMatch()           第 173 行   ← 域名匹配语义
   - shouldApply()            第 199 行   ← 是否该隐藏（白名单判定点）
6. adblocker/src/shared/validate.js           ← 267 行，云端数据防线（安全关键）
7. adblocker/src/shared/auth.js               ← 2467 行，账号与同步（最复杂，建议最后读）
```

> 行号会随改动漂移。上面的入口函数名比行号更可靠——用编辑器搜函数名定位。

**不要一上来就读 `options.js`（1965 行）和 `auth.js`（2467 行）**——
它们是 UI 层与业务层，依赖前面那些才看得懂。

## 三、术语表

| 术语 | 含义 | 在哪出现 |
|---|---|---|
| **DNR** | Declarative Net Request，Chrome 的声明式网络请求拦截 API。规则由浏览器引擎执行，不进扩展进程 | `background.js` 全局 |
| **静态规则集** | 打包进扩展、由 Chrome 编译的规则（`rules/*.json`）。ruleId 固定，扩展代码改不了 | `rules/`、`manifest.json` |
| **动态规则** | 运行时由 JS 下发的规则。ruleId 由扩展分配，**全局唯一** | `background.js` |
| **段位** | 动态规则 ID 的分段规划。用户 100000~ / 站点 200000~ / 订阅 300000~ / 全局放行 2000000 | `AGENTS.md` 硬性约定 2 |
| **世界（world）** | content script 的执行环境。隔离世界能用 `chrome.*` 但页面看不见；MAIN world 页面看得见但不能用 `chrome.*` | `manifest.json` 的 `world` 字段 |
| **隔离世界 / MAIN world** | 见上 | `anti-detect.js` / `anti-detect-main.js` |
| **nonce** | 一次性随机串，用于隔离世界与 MAIN world 互相验证，防页面伪造消息 | `anti-detect.js` |
| **诱饵（bait）** | 伪装成广告位的 DOM/CSS，让反拦截脚本以为广告还在 | `anti-detect.js` |
| **ABP 语法** | Adblock Plus 的过滤规则语法。`\|\|domain^` 拦域名，`domain##.sel` 隐藏元素，`@@` 表示例外 | 规则解析器 |
| **白名单** | 暂停拦截的站点列表。**存储形式是归一化后的裸域名** | `shared/host.js` |
| **子域匹配** | 存 `example.com` 时 `www.example.com` 也算命中。与 DNR `requestDomains` 语义一致 | `shared/host.js` |
| **订阅** | 在线拉取的过滤列表，转换后写进动态规则的订阅段 | `background.js` 订阅模块 |
| **订阅段位** | 每个订阅占 10000 个 ruleId，按 `id % 100` 分。id 撞号会互相覆盖 | `AGENTS.md` 硬性约定 2 |
| **feedback 权限** | `declarativeNetRequestFeedback`，**仅对未打包扩展生效**。正式安装版请求级统计因此受限 | `AGENTS.md` 已知平台限制 |
| **activeTab** | 用户点击扩展图标时授予的临时权限。正式版按标签页查命中计数的唯一路径 | `manifest.json` 权限 |
| **CRX / CRX3** | Chrome 扩展安装包。CRX3 的头里含公钥，扩展 ID 由它派生 | `pack.ps1` |
| **扩展 ID** | 由签名公钥派生。**换密钥 = 换身份**，自动更新链路会断 | `pack.ps1` |
| **单一真源** | 一项能力只允许有一份实现（host 归一化、转义、默认设置、消息协议、校验、弹窗） | `AGENTS.md` 第 1 节 |
| **内存缓冲** | `__statsBuffer`，统计的实时内存态。SW 挂起即丢，所以要同时落盘 | `background.js` |
| **抑制窗口** | 云端拉取后短暂阻止"写本地 → 自动上传"的回环 | `auth.js` |

## 八、风险预案

### 8.1 技术风险

| 风险 | 等级 | 触发信号 | 应对动作 |
|---|---|---|---|
| 动态规则池耗尽 | 中 | `npm run probe` 显示占用率 ≥90% | 停用订阅或减少规则量；`applyUserRules` / `applySubscriptionText` 会截断并回传被丢弃条目 |
| 正式版统计缺失 | 中 | 用户反馈"正式安装后统计是空的" | **不是 bug**，是 feedback 权限限制。正式版只有"本站已拦截"计数可用。UI 已如实说明，别去"修"它 |
| 云端数据被污染 | 中 | 用户规则/白名单莫名变化 | `shared/validate.js` 是唯一防线，改它之前先看 `tools/test-validate.mjs` 的 100 项断言 |
| 订阅源返回错误页 | 低 | 订阅更新报"未解析出任何可用规则" | 已有保护：解析为空时**不下发**，不会清空原规则。修这条逻辑时务必保留它 |
| Chrome 升级改 API 形态 | 低 | 某个 `chrome.*` 调用突然 undefined | 用 `npm run probe` 实测，不要凭记忆。如 `getAvailableConstants()` 在 156 上已不存在 |

### 8.2 协作风险

| 风险 | 等级 | 触发信号 | 应对动作 |
|---|---|---|---|
| 两个协作者改同一文件 | 中 | 出现"看起来对但静默失效"的改动 | 本项目**没有 git 仓库**，无法 diff/回滚。改大文件前先备份，或先做一次全量 `npm run verify` 留基线 |
| 违反单一真源 | 中 | `npm run check` 报"自带了 XX 实现" | 改用共享模块，别复制一份 |
| 知识不回流 | 低 | 新坑只有当事人知道 | 记进 `.learnings/`，并在代码处留编号引用（`AGENTS.md` 第 4 节） |
| 文档与代码漂移 | 低 | 文档说的和代码做的不一致 | 改代码时同步改文档；`npm run check` 只能校验一部分 |

### 8.3 发布风险

| 风险 | 等级 | 触发信号 | 应对动作 |
|---|---|---|---|
| 签名密钥丢失/更换 | **高** | 扩展 ID 变化、已装用户收到"新扩展" | 密钥必须放项目外（`ADSHIELD_KEY` 或 `D:\AdShield-Keys\`）。**绝不要把密钥提交进版本库或随项目目录分发** |
| 静态规则集在打包版被静默忽略 | 中 | 开发模式正常、打包版失效 | Chrome 对无效静态规则只在未打包时报警。改 `rules/*.json` 后必须用 `npm run probe` 验证端到端自检 |
| 版本号与 manifest 不一致 | 低 | `pack.ps1` 打印的版本对不上 | `pack.ps1` 会自动改写 `manifest.json` 的 version，打包后确认一次 |

## 九、遗留路线图

按优先级：

| 优先级 | 事项 | 状态 | 说明 |
|---|---|---|---|
| **P1** | **i18n** | ⬜ 未做 | 全项目 `chrome.i18n` 0 命中，`_locales` 只有名称与描述两个键。英文用户看到的 UI 全是中文（LRN-20261031-004） |
| **P2** | 订阅更新失败的分类提示 | ⬜ 未做 | 目前只报"未解析出任何可用规则"，没区分"CDN 挡了"和"格式不支持" |
| **P2** | `options.css` 拆分（2641 行） | ⬜ 未做 | 样式与 `options.html` 强耦合，改动回归面大 |
| **P2** | 导出入口统一 | ⬜ 未做 | 现有 5 个导出入口（备份 / 统计 / 日志 JSON / 日志 CSV / 元素隐藏规则），分布在 popup、options、logger 三处，格式与命名各不相同 |
| **P3** | 订阅规则的精细分类 | ⬜ 未做 | 正式版把所有动态规则归为"广告"，分类图不准 |
| **P3** | `anti-detect` 效果实测 | ⬜ 未做 | 需在真实反拦截站点验证伪装是否有效 |

**做之前先想清楚**：i18n 是一次独立的大改（所有 UI 文案抽成 `_locales` 键），
建议单独排期，不要混在功能需求里做。
